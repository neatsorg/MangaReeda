# プラグイン機能について

MangaReeda のプラグイン機能は、ブックリストの拡張にまつわるものと、文字列情報が埋め込まれていないPDFなどに対して本文検索ができるようにする OCR エンジンを拡充するものがあります。

ブックリスト用のプラグインでは、標準機能であるローカルフォルダ、履歴、お気に入りのほかに、クラウドサービス上の本の一覧をタブとして並べられます。  
サンプルとなる本体同梱のプラグインとして、Dropbox のフォルダを読む `mangareeda-dropbox`（[下記](#dropbox)）、Google Drive のフォルダを読む `mangareeda-gdrive`（[下記](#google-drive)）があります。BOOKSCAN の本棚を読む `mangareeda-bookscan`（[下記](#bookscan)）は、本体とは別のファイルで配っています。

また OCR エンジン用のプラグイン（[下記](#ocr-用のプラグイン)）では、標準機能である Windows.Media.Ocr（Windows の場合）または Tesseract（Linux の場合。要追加インストール）以外に、manga-ocr や RapidOCR などのエンジンを使えるようにできます。

MangaReedaとプラグインは標準出力を使ってやり取りします。
プラグインはどの言語で書いても構いません。

## プラグインの置き場所

`~/.config/MangaReeda/plugins/<名前>/plugin.json` に下記のような説明ファイルを置きます（`XDG_CONFIG_HOME` があればその下）。

```json
{
  "id": "example",
  "name": "Example",
  "command": ["./example.py"],
  "credentials": [
    { "key": "token", "label": "API トークン", "secret": true }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `id` | プラグインの名前。ダウンロード先のフォルダ名や、ログイン情報の保存にも使う |
| `name` | タブに出す名前 |
| `command` | 実行する命令と引数。`./` で始まるものは `plugin.json` のフォルダから探す |
| `credentials` | 設定画面で入力してもらう項目。`secret` が真（true）の場合は設定画面上で伏せ字になる。`hidden` が真の場合は設定画面じたいに出さない（プラグインが `store` で保存する値に使う）。省略可 |
| `auth` | 真なら、設定画面に「ブラウザで許可する」ボタンを出し、`auth-url` を呼ぶ。ブラウザ認証用。省略可 |
| `kind` | プラグインの種類。`"books"`（本の一覧。省略したとき）または `"ocr"`（[OCR](#ocr-用のプラグイン)） |
| `ocr_batch` | OCR のプラグインに一度に渡すページの数（1〜128）。省略時は 16。起動の準備（モデルの読み込みなど）に時間がかかるエンジンは大きくする |

## プラグインとのデータのやり取り

MangaReeda はまず次のどちらかの引数を付けて `command` を起動し、標準入力に1行の JSON を書きます。コマンドライン引数ではなく標準入力で渡すのは、ほかのプロセスから見えないようにするためです。

```json
{"credentials": {"token": "…"}}
```

デフォルトだとログイン情報は OS のキーリングに保存されますので、外部からは参照できません。キーリングが使えない環境では、MangaReedaが起動しているあいだだけメモリに記録されています。したがって、起動のたびに認証情報の入力が必要になります。

### `list [<フォルダ>]`

本の一覧を返します。フォルダ名を渡された場合は、その内容を返します（フォルダ名を渡されない場合は一番上を返します）。標準出力の最後の行に、次の JSON を書いてください。

```json
{"books": [
  {"id": "…", "title": "フォルダ名", "file_name": "フォルダ名", "folder": true},
  {"id": "…", "title": "書名", "file_name": "書名.pdf", "cover_url": "https://…/cover.jpg"}
], "parent": "", "account": "…"}
```

| 項目 | 意味 |
|---|---|
| `id` | プラグインの中での本の名前。`download` のときにそのまま渡す |
| `title` | 表紙の下と、選んだときの説明に出す |
| `file_name` | ダウンロードした本のファイル名。MangaReeda が開ける形式（`.zip` `.cbz` `.rar` `.cbr` `.pdf`）にする |
| `cover_url` | 表紙の画像の URL。省略可。MangaReeda が取りに行き、手元にためる。Webサービス側に負担をかけないよう、1枚ずつ1秒空けて取得する（15秒で答えが無ければあきらめ、遅かったときは10秒空ける）。取得できなかったものについては1日（時間切れのときは7日）取りに行かない。ユーザーが本じたいをダウンロードした場合は、そちらから表紙画像を作り、サーバには取りに行かない |
| `cover_data` | 表紙の画像そのもの（base64、2MB まで）。省略可。表紙画像の URL がすぐに失効する、取得にログインが要るなど、MangaReeda が取りに行けない表紙を渡すときに使う。MangaReeda は手元に置き、ユーザーが次に一覧を取り直すまでそれを使う |
| `folder` | 真ならフォルダを表す。選ぶと、その `id` を付けて `list` を呼ぶ。省略可 |
| `parent` | 上位フォルダ（`list` に渡す値）。最上位の場合は省く。あれば「上のフォルダ」と Backspace で移れる |
| `message` | ユーザーに見せる一言（表紙を取得できた数など）。省略可。次に取り直すまで、タブの右に出る |
| `account` | いま使っているアカウントを見分ける値（アカウントの id やメールアドレスなど）。省略可。MangaReeda は値そのものは保存せず、そこから作った短い値だけを手元に置き、アカウントが変わったら別の本として扱う |

`file_name` は `/` で区切ってフォルダを含められる（クラウドのフォルダの並びをそのまま保つため）。ただし `..` などでダウンロード先の外に出ることはできないようになっている。

一覧を取るのに時間がかかるときは、`download` と同じ形の進み具合の行（`{"progress": 12, "total": 60}`）を書くと、「更新中」の横に出せる。

ファイル一覧はフォルダごとに MangaReeda が手元にためておき、次からはそれが使われる。取り直すのは、ユーザーが「更新」を押したとき（キーバインド：F5）と、設定画面でログイン情報を変えたときだけです。
タブを開くと、最後に見ていたフォルダから開くことができます。
返ってきた `account` が前と違う場合は、過去にためておいたフォルダ一覧と、中断されているダウンロードを捨てます。

### `download <id> <保存先>`

本を `<保存先>` のファイルに書きます。途中で止まっても壊れたファイルが残らないよう、同じフォルダの別の名前（ほかのファイルと重ならないもの）で書いてから名前を変えてください。そのとき `<保存先>` にすでにファイルがあれば、置き換えずに失敗としてください。

進み具合は、標準出力に1行ずつ次の JSON を書くと、表紙の下に出ます（大きさがわからなければ `total` を省く）。

```json
{"progress": 1048576, "total": 52428800}
```

ダウンロードは1冊ずつ順に行います。並列処理はされません。

### `auth-url`

`auth` が真のプラグインに対して使用されます。ブラウザで認証するページの URL を、標準出力の最後の行に書いてください。MangaReeda がそのページを既定のブラウザで開きます。

```json
{"url": "https://…"}
```

### 値の保存（`store`）

どの命令でも、標準出力に次の行を書くと、MangaReeda がその値をログイン情報としてキーリングに保存し、次から標準入力で渡します。値が空なら消します。トークンを取り替えたときなどに使います。

```json
{"store": {"refresh_token": "…", "auth_code": ""}}
```

### 時間の上限

プラグインが答えを返さなくなっても MangaReeda が止まらないよう、次の時間を過ぎたらプラグインを止め、失敗として知らせます。

| 命令 | 上限 |
|---|---|
| `list` | 終わるまで 10 分（進み具合の行を書けば、最後の行から 10 分） |
| `auth-url` | 終わるまで 30 秒 |
| `download` | 進み具合の行が届かないまま 3 分 |

止めるときは、プラグインが起動したプロセスもまとめて止めます（Unix ではプロセスグループ、Windows ではジョブオブジェクト）。プラグインが終わったときに残っているプロセスも止めます。ダウンロードでは、少なくとも数十秒ごとに進み具合を書くようにしてください。

### 終わり方

| 終了コード | 意味 |
|---|---|
| 0 | 成功 |
| 2 | ログインできなかった。設定画面でログイン情報を入れるよう促す |
| ほか | 失敗。標準エラーの最後の行を利用者に見せる |

## ダウンロードした本

設定画面の「プラグイン」で指定したフォルダ（既定はホームの `MangaReeda`）の下に、`<プラグインの id>/<file_name>` として置きます。

ダウンロード済みの本は、選ぶとそのまま開くことができます。

どの本をどこに置いたかは、どのアカウントの本かとあわせて `<プラグインの id>/.mangareeda-downloads.json` に記録します。名前が同じ別の本（同じ一覧の中で重なるもの、前に別の本や別のアカウントの本を置いた場所、ダウンロード中や待っている別の本の場所と重なるもの）は、`名前~xxxxxxxx.pdf` のように本の id とアカウントから作った印を付けて別の場所に置き、取り違えないようにします。

もし記録がないファイルがあった場合は、どの本かわからないので開かず、名前が重複する場合と同様に、印を付けた別の場所にダウンロードし直します。もとのファイルは消しません。

## OCR 用のプラグイン

`"kind": "ocr"` のプラグインは、本の中の検索で、文字の層（PDF の透明テキスト）の無い本のページを読みます。
検索の窓で「OCR で文字を読む」を押すと、MangaReeda はページを PNG の画像にして（長い辺は 2400 ピクセルまで）、`ocr` の命令で何ページかずつ渡します。
OCR のプラグインが複数あるときは、設定画面の「プラグイン」で使うものを選べます。

マンガ向けの [manga-ocr のプラグイン](../plugins/manga-ocr/README.md)（GPL-3.0）も用意しています。しかし重いため、本体には同梱していません。使いたい人は `plugins/manga-ocr/install.sh` から入れてください。

軽めのものとして、[RapidOCR のプラグイン](../plugins/rapidocr/README.md)（Apache-2.0）もあります。CPU でも1ページ1秒ほどで、マンガも縦書きの本も読めます。Linux は `plugins/rapidocr/install.sh`、Windows は `plugins/rapidocr/install.ps1` から入れてください。

### `ocr`

標準入力の1行に、ログイン情報と画像を渡します。

```json
{"credentials": {"api_key": "…"}, "images": [{"page": 0, "path": "/…/page-00000.png"}, {"page": 1, "path": "/…/page-00001.png"}]}
```

読み終えたページから、標準出力に1行ずつ次の JSON を書いてください。順番は問いませんが、返すのは渡したページだけ、同じページは一度だけにしてください（それ以外が届くと、その本の結果は使いません）。`text` は省けません。文字が無いページは `text` を空にします。

```json
{"page": 0, "text": "ページの文字"}
```

行の区切りは改行のままでかまいません（検索では空白と改行を無視します）。

ページが届くたびに時間の上限（5 分）を数え直すので、準備に時間がかかるエンジンは、最初のページを返すまでを 5 分以内にしてください。

結果を返さなかったページは「読めなかったページ」として数えます。読めたページの結果は保持し、読めなかったページの数を知らせます（自動では読み直しません。読み直すときは「ツール」→「OCR で本の文字を読み直す...」）。1ページも読めなかったときは失敗として扱い、前に読んだ結果をそのまま残します。

## 作者提供のブックリスト用プラグインについて

### Dropbox

`mangareeda-dropbox` は、Dropbox のフォルダをたどり、書庫と PDF をダウンロードします。

使用するには自分の Dropbox アカウントでデベロッパーコンソールにアプリを1つ登録し、その App key を使います（無料）。読むための権限だけが使われます。

1. <https://www.dropbox.com/developers/apps> で「Create app」を押す
   - API: Scoped access
   - アクセスの種類: Full Dropbox（今ある本を読むため）
   - 名前: 好きな名前（ほかの人と重ならないもの）
2. できたアプリの「Permissions」で `files.metadata.read` と `files.content.read` に印を付けて「Submit」を押す（`account_info.read` は初めから付いています。接続したアカウントを見分けるのに使います）
3. 「Settings」の「App key」を写す（App secret は使いません）
4. MangaReeda の設定画面の「プラグイン」→「Dropbox」で App key を保存し、「ブラウザで許可する」を押す
5. ブラウザが開き、認証画面になる。許可していくと認可コードが出るので、設定画面の「認可コード」の欄に貼って保存する
6. 表紙サムネイルの「Dropbox」タブを開く

許可を取り消すときは、Dropbox 上から「設定」→「接続済みのアプリ」で行えます。

Dropbox ではダウンロードしていないファイルに対して表紙を表示できません。ダウンロードした本については、ファイルから表紙を作ることができます。「ブックリスト」メニューから、任意のページを表紙にすることも可能です。

### Google Drive

`mangareeda-gdrive` は、Google Drive のマイドライブのフォルダをたどり、書庫と PDF をダウンロードします。

接続には、自分の Google アカウントで Google Cloud のプロジェクトを1つ作り、OAuth クライアントを登録して使います（無料）。読むための権限（`drive.readonly`）だけを使います。

1. <https://console.cloud.google.com/> でプロジェクトを作る
2. 「API とサービス」→「ライブラリ」で「Google Drive API」を有効にする
3. 「Google Auth Platform」（OAuth 同意画面）を設定する
   - 対象: 外部
   - アプリ名やメールアドレス: 自分のもの
   - 「対象」の公開ステータスは「本番環境」にする（「テスト」のままだと、許可が7日で切れます）
4. OAuth クライアントを作る。メニューの「API とサービス」→「認証情報」→「＋ 認証情報を作成」→「OAuth クライアント ID」（画面の版によっては「Google Auth Platform」→「クライアント」→「＋ クライアントを作成」）で、アプリケーションの種類に「デスクトップ アプリ」を選んで作成する
   - できたクライアント ID（`….apps.googleusercontent.com` で終わる長い値。プロジェクト ID とは別のもの）とクライアント シークレットを書き写しておく
   - シークレットは作った直後にしか見られないことがあるので、その画面で確実に書き写すか、JSON をダウンロードしておきましょう
5. MangaReeda の設定画面の「プラグイン」→「Google Drive」でクライアント ID とクライアント シークレットを保存し、「ブラウザで許可する」を押す
6. ブラウザで Google アカウントを選び、許可する
   - 「Google はこのアプリを確認していません」と出たら、「詳細」→「（アプリ名）に移動」で許可して先に進む（自分で作ったアプリなので、この警告は無視する必要がある）
7. 最終的にブラウザには `http://127.0.0.1:47853/?code=…` ではじまる URL のページが表示され、「接続できません」と出るはずです。それで正常なので、その URL をまるごとコピーし、設定画面の「許可したあとのページの URL」の欄に貼って保存する
8. 表紙サムネイルの「Google Drive」タブを開く

デスクトップ アプリのクライアント シークレットは、ほかの人に教えないでください。

許可を取り消すときは、Google アカウントの「セキュリティ」→「サードパーティ製のアプリとサービス」から行います。

一覧表示できるのはマイドライブだけです（「共有アイテム」と共有ドライブには対応しません）。Google ドキュメントなど、このソフトが対応していないファイルは表示しません。

表紙は、Google Drive が自動で作ったサムネイル（PDF など）を取得しています。サムネイルのないもの（書庫など）については、Dropbox と同様にダウンロードした本から作ります。

### BOOKSCAN

MangaReeda 本体には同梱していません。

作者は BOOKSCAN が素晴らしいサービスであり永遠に続いてほしいと願っているため、極力、サーバ負荷を軽減する設計にしてあります。

`mangareeda-bookscan` は、[BOOKSCAN](https://www.bookscan.co.jp/) の本棚にある本の一覧を返し、PDF をダウンロードします。
リリースのファイルを使うときは、`mangareeda-bookscan-<版>-<OS>-x64` の中のプログラムを `mangareeda` と同じフォルダに置きます。`cargo build --release --workspace` でビルドしたときも `mangareeda` と同じフォルダにできます。そこにあれば自動で使えます。

1. 設定画面の「プラグイン」で、BOOKSCAN のメールアドレスとパスワードを入れて保存する
2. 表紙サムネイルの「BOOKSCAN」タブを開くと、本棚の一覧を取りに行く
3. 本を選ぶと PDF をダウンロードし、終わったら開く

BOOKSCAN の利用規約に従って使ってください。サイトに負担をかけないよう、本棚のページは間を空けて取り、ダウンロードは1冊ずつ行います。一覧の更新も、自動では行われません。
また、サイトの作りが変わると動かなくなることがあります。

表紙画像は、サイトに負担をかけないよう1枚ずつ取るので、初めて一覧を開いたときは、かなり時間がかかります（画面に見えている本から取得していきます）。表紙のない本ではサイトの応答が遅くなるため、15秒であきらめ、7日たってからまた取りに行きます。

事前にブラウザで BOOKSCAN にログインして本棚を開いてからこのプラグインで一覧表示をすると、取得がわずかにスムーズになる可能性があります（保証はありません）。一度取得した表紙はローカルに保存されるため、次からは取りに行きません。

表紙のないものについては、Dropbox などと同様に、ダウンロードした本から作ることができます。

参考にしたもの: [snaka/download-bookscan](https://github.com/snaka/download-bookscan)（MIT License）。コードは含みません。
